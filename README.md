# 招标辅助核对

一个面向采购/投标专员的离线可演示网页应用，包含两个核对工具：

1. **招标截标状态核对**（首页 `/`）
2. **答疑核对**（`/qa`）：编标书前确认采购网站上的询问哪些已有正式答复、哪些还要向采购人求证。

## 答疑核对

在 **答疑核对** 页面输入**项目编号**和**答疑目录网址**后，系统会：

1. 从目录页出发，仅跟踪同一站点的分页链接，逐页读取标有问题编号的提问与答复详情；
2. 按归一化后的问题编号将提问与答复配对；
3. 答复可通过同站链接或修订文字引用前一条答复；系统沿引用链确定先后，**只以链上最新的“有效”答复为准**，声明作废、撤销或无效的答复不计入；
4. 网页按问题显示答复状态（**已有正式答复 / 尚未答复 / 待核实**）、答复正文、修订引用链，以及提问方与答复方的双方来源链接。

### 答疑判定规则

- **已有正式答复**：引用链完整，且链上至少存在一份未声明作废的有效答复，最新有效答复作为结论。
- **尚未答复**：分页已全部读取完成，确实没有该问题的有效答复——编标前应就此类问题向采购人/代理机构书面求证。
- **待核实（仅该问题，不影响其他问题）**：
  - 引用链断裂、分叉或循环，引用的前序答复不在目录中或抓取失败；
  - 同一发布时间出现两份未声明修订关系的答复，内容冲突无法自动判定；
  - 已标号的提问或答复详情页抓取失败；
  - 提问详情缺失或同一编号存在多个提问，配对存在歧义。
- **分页失败的处理**：保留已采集的全部内容，并标记分页不完整；此时缺少答复的问题**不会被判为“尚未答复”**，而是“待核实”，避免在未读全的情况下下结论。

### 答疑样本项目

样本站点新增 `sample_site/qa/` 目录（3 个分页 + 详情页），并提供 `/qa/broken/page-1.html` 断链演示：

| 项目编号 / 问题 | 演示场景 | 预期结论 |
|---|---|---|
| `GSB-2026-001` / Q1 | 初版答复 → 已作废的修订二 → 修订三，跨页重复条目 | 已有正式答复，以修订三为准 |
| `GSB-2026-002` / Q2 | 同一发布时间两份口径冲突的答复 | 待核实 |
| `GSB-2026-003` / Q3 | 修订答复引用了目录中不存在的前序答复 | 待核实（引用链不完整） |
| `GSB-2026-004` / Q4 | 已标号答复详情页返回 404 | 待核实（仅该问题） |
| `GSB-2026-005` / Q5、Q7 | Q5 已答复、Q7 仅有提问 | Q5 已有正式答复，Q7 尚未答复 |
| 断链目录 | 第 2 页链接失效 | 保留第 1 页内容，缺答复问题为待核实而非尚未答复 |

## 招标截标状态核对

输入**项目编号**和**公告列表网址**后，系统会：

1. 从列表页出发，仅跟踪同一站点的分页链接；
2. 抓取与项目编号匹配的公告详情页；
3. 按发布时间串联原公告、更正公告和取消公告；
4. 合并跨页或镜像重复公告；
5. 输出“可投标 / 已截止 / 已取消 / 待核实”，并列明结论依据的标题、发布时间和来源链接。

## 快速启动（Docker Compose）

```bash
docker compose up --build
```

启动后访问：

- 核对应用（截标状态）：<http://localhost:5000/>
- 核对应用（答疑核对）：<http://localhost:5000/qa>
- 本地分页样本站点：<http://localhost:8080>
- 样本公告列表页：<http://localhost:8080/notices/page-1.html>
- 样本答疑目录页：<http://localhost:8080/qa/page-1.html>

Compose 包含两个服务：

- `web`：Flask + requests + BeautifulSoup 核对应用；
- `sample-site`：使用 Python 静态文件服务器提供的本地分页样本站点。

Web 容器会把浏览器可访问的 `http://localhost:8080` 自动映射为容器网络内的 `http://sample-site:8080`，因此页面中展示的仍然是宿主机可点击的来源链接。

## 样本项目

以样本站点当前虚构数据、系统日期为 2026-11-11 时为例：

| 项目编号 | 演示场景 | 预期结论 |
|---|---|---|
| `GSB-2026-001` | 原公告后两次更正，跨页重复公告被合并 | 可投标，截标时间 2026-11-27 17:00 |
| `GSB-2026-002` | 取消公告后还有普通延期更正 | 已取消，后续更正不恢复招标 |
| `GSB-2026-003` | 同一发布时间两条更正给出不同截标时间 | 待核实 |
| `GSB-2026-004` | 相关更正详情页返回 404 | 待核实 |
| `GSB-2026-005` | 截标时间已过 | 已截止 |

> “可投标/已截止”会随运行时的系统日期变化；样本项目的取消、冲突和详情失败规则不变。

## 样本站点页面结构

样本站点模拟常见政府采购网站结构：

- 公告列表页：`sample_site/notices/page-1.html`、`page-2.html`、`page-3.html`
  - 每条公告位于 `.notice-item`；
  - 详情链接位于条目的 `h2 a`；
  - 项目编号位于 `.project-no` 或 `data-project-no`；
  - 发布时间使用 `<time datetime="...">`；
  - 分页链接位于 `.pagination`，包含页码和 `rel="next"`。
- 公告详情页：`sample_site/detail/*.html`
  - 标题位于 `h1`；
  - 项目编号、公告类型和发布日期位于 `.publish-meta`；
  - 正文包含“投标截止时间”“延期至”等常见表述。
- 答疑目录页：`sample_site/qa/page-1.html`、`page-2.html`、`page-3.html`（断链演示在 `sample_site/qa/broken/`）
  - 每条提问/答复位于 `.notice-item`，并带 `data-question-no` 与问题编号文字；
  - 答疑详情页位于 `sample_site/qa/detail/*.html`，在 `article` 上标注 `data-question-no`、`data-entry-type`（供应商提问/采购人答复）；
  - 答复中的修订引用是带 `.answer-reference` 的同站链接，或“修订对问题 N 前一条答复”之类文字；
  - 作废答复在正文中声明“本答复作废/无效/撤销”。

抓取器并不只依赖这些固定 class：它还会识别常见的 `article/li/tr` 列表结构、分页文字、详情页 `meta` 时间、中文日期格式，以及“响应文件提交截止时间”“开标时间”等标签。

## 判定规则

- **可投标**：未发现取消公告，且按时间链得到的最新截标时间晚于当前时间。
- **已截止**：未发现取消公告，但最新截标时间不晚于当前时间。
- **已取消**：发现取消/终止/废标类公告；其后的普通更正公告只展示在时间链中，不恢复招标。
- **待核实**：
  - 与项目相关的详情页抓取失败；
  - 同一发布时间的更正公告给出互相冲突的截标时间；
  - 分页或详情数量超过安全上限；
  - 缺少关键发布时间或有效截标时间；
  - 未找到与项目编号匹配的公告。

## 本地开发（不使用 Docker）

需要 Python 3.11+。

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt

# 终端 1：启动样本站点
python -m http.server 8080 --directory sample_site

# 终端 2：启动核对应用
python app.py
```

然后访问 <http://localhost:5000>，答疑核对入口位于页面顶部标签或直接打开 <http://localhost:5000/qa>。

## 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `5000` | Web 应用监听端口 |
| `DEMO_PROJECT_NO` | `GSB-2026-001` | 表单默认项目编号 |
| `DEMO_LIST_URL` | `http://localhost:8080/notices/page-1.html` | 截标核对表单默认列表网址 |
| `DEMO_QA_CATALOG_URL` | `http://localhost:8080/qa/page-1.html` | 答疑核对表单默认目录网址 |
| `SAMPLE_SITE_PUBLIC_URL` | 空 | 浏览器侧样本站点地址 |
| `SAMPLE_SITE_INTERNAL_URL` | 空 | 容器网络内样本站点地址 |
| `MAX_LIST_PAGES` | `15` | 截标核对最多抓取的列表分页数 |
| `MAX_DETAIL_PAGES` | `80` | 截标核对最多抓取的详情页数 |
| `MAX_QA_LIST_PAGES` | `10` | 答疑核对最多读取的目录分页数 |
| `MAX_QA_DETAIL_PAGES` | `60` | 答疑核对最多抓取的详情页数 |
| `FLASK_SECRET_KEY` | 开发默认值 | Flask 密钥，生产环境应覆盖 |

## 边界说明

- 仅抓取静态 HTML，不执行 JavaScript；
- 分页跟踪限制在同一站点（同一 scheme、主机和端口），答疑修订引用同样只接受同站链接；
- 单个 HTML 页面默认最大 5 MB；
- 详情页请求超时后只会把对应公告或对应问题标记为“待核实”，不会猜测结论，也不影响其他问题；
- 答疑目录分页未读全时，缺少答复的问题标记为“待核实”而非“尚未答复”；
- 抓取结果用于辅助核对，正式投标前仍应以采购人或代理机构的书面确认为准。
